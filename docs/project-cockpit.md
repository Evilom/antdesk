# 个人 PM · P0 项目驾驶舱

入口：宠物 → 主面板 → 和我聊聊 → 项目驾驶舱。驾驶舱位于原助理面板内，通话控制保留在下方。

## 工程事实

应用安装后，由用户在每台设备上指定可读取的项目或参考文件夹。普通参考文件夹可用于按问题检索，不要求 Git 仓库。连接 Git 根目录时，每 15 秒显示当前分支、提交、暂存/未暂存/未跟踪文件与冲突。采集只读，不执行项目构建脚本，不读取上级未授权仓库。断开目录后停止提供该目录的新数据。

GitHub `origin` 仓库通过本机已有的 `gh` 登录读取最近 5 次 Actions 运行，缓存最多 60 秒。未安装 `gh`、未登录、非 GitHub 仓库或查询失败会明确显示不可用，不会推断构建通过。

每个构建结果都带时间、来源和提交范围：旧提交的成功不代表当前提交成功；工作区有改动时，CI 不能验证当前未提交代码。工作区在采集期间仍可能变化，界面是有时间戳的快照，不是文件锁。

### 接入本地构建与测试

AntDesk 无法观察任意终端中过去运行的命令。需要记录的命令使用随项目提供的包装脚本运行，例如在 AntDesk 仓库内：

```sh
python3 scripts/pm-check.py --kind build --label "前端生产构建" -- yarn build
python3 scripts/pm-check.py --kind test --label "Rust 单元测试" -- cargo test --locked --manifest-path src-tauri/Cargo.toml --lib
```

其他已连接项目可从自己的工作目录调用该脚本的绝对路径。脚本执行您明确指定的命令，保留其退出码，将开始和结束事件追加至项目 `.antdesk/checks.jsonl`。不保存命令参数或输出，避免混入凭据；不重写已有记录。可将 `.antdesk/` 加到该项目的忽略规则中。

“已启动，尚无结束记录”只表示记录器写下开始事件，不保证进程仍在运行。机器断电或记录器被强制终止时不会伪造完成结果。只有相同提交、开始/结束均为干净工作区且当前工作区干净时，结果才标为对应当前版本。

## 工作包与节点

在驾驶舱点“＋ 工作包”，选择已连接项目，填写工作包名称、交付目标和节点。节点包含状态、目标日期、下一步、阻塞原因以及前置依赖。

- 前置节点未完成或存在阻塞的节点，不列入“可推进”。
- 标为完成是用户登记的计划状态，不是代码或交付物已通过验收。
- 保存会在现有 PM SQLite 中新增工作包版本，不改写对话和长期记忆。
- 每次保存都可在修改时间线查看；界面展示最近 40 次，数据库保留完整历史。
- 两个窗口同时修改同一版本时，后保存的窗口会提示重新读取，避免覆盖。
- 目录断开后，对应工作包保留在数据库中，但不会提供给语音；重新连接后可恢复查看。

新语音连接与后续提问会重新获取工程事实和工作包。上下文有明确长度上限，会优先选择提问相关的工作包并标记截断。工作包在实际使用时指定，不预置具体业务项目；未登记的节点不会根据聊天自动填入或猜测为完成。
