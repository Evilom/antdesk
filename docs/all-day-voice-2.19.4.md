# 网页语音全天连续对话（v2.19.4）

原实现默认每 1800 秒结束 WebRTC 并申请新的网页语音会话。这个到期时间来自本机 `chatgpt-web-voice` 网关的会话登记，并非 OpenAI Realtime API 的时长限制。AntDesk 自己的聊天 ID 原本不会定时更换，但重连只注入最近六条消息，并要求再次问候。

现在支持网关登记续期：客户端每 20 秒更新同一个登记，保留原来的网页 WebRTC 连接、麦克风和上游账号绑定，不重新创建网页语音会话。暂时的续期网络错误不会拆掉仍有效的媒体连接。过期、真正断线或网关重启才走旧连接释放和恢复流程；账号拒绝、撤销及上游额度结束信号仍然生效。旧网关没有 `session_renewal` 能力时保持兼容的到期重连行为。

AntDesk 的同一条对话持续保留，跨午夜不自动新建。只有用户主动选择“新对话”才另开聊天；即使新对话还没有消息，重启也能恢复该选择。当前对话过去 24 小时的文字、语音转写及已接入项目的状态采集保存在本机追加日志中，不删除较早记录。重连读取全天的时间段节选、近期消息和查询匹配内容；助理历史回答单独注明未验证，工程采集时间不代表工作耗时。界面提供“全天记录”入口、关键词检索及滚动阅读。

电脑休眠、退出、网络或网页服务中断仍可能结束语音。断线恢复目前依靠 AntDesk 保存的上下文，不能保证沿用同一个 ChatGPT 网页对话编号，也不能宣称上下文节选覆盖了未采集的活动。此次没有增加后台屏幕采集或额外录音。

## 网关配套变更

当前 Mac 的 `chatgpt-web-voice` 服务已应用更新并重启，健康检查及在线 OpenAPI 续期路由已确认。生产账号没有用于测试会话。

仓库附有 `docs/gateway-session-renewal.patch`，用于已部署 `/v1` 集成接口的 `chatgpt-web-voice` 网关：新增 `POST /v1/realtime/sessions/{id}/renew`，只允许当前有效设备续期自己的未过期会话。接口不返回凭据，不选择新账号，不创建新的上游媒体会话。续期时刷新现有图片上传账号绑定的访问时间。停止客户端后，登记仍按租约清理。

其他网关部署先使用 `git apply --check /path/to/gateway-session-renewal.patch` 检查适配，再应用并运行配套测试。`tests/gateway-session-renewal.py` 是该网关的 pytest 测试，应在其 Python 环境下运行；AntDesk 不引入 Python 运行时。网关原有未提交的设备接入等工作未混入本次 AntDesk 发布。

## 验证

- 前端生产构建及 54 项 JavaScript 测试通过。
- 使用真实客户端逻辑和模拟时钟完成 24 小时以上、4321 次续期：只有 1 次创建、1 个麦克风、没有重复上下文问候，停止后不再续期。
- 覆盖真实断线的模拟恢复、先释放后创建、静音保留、旧网关兼容、短暂续期失败和停止后迟到响应。
- Rust 检查通过；27 项测试通过、2 项需本机服务的测试按原配置跳过，覆盖全天 300 条记录后的早间关键词检索、跨午夜、原始顺序、消息修订去重、显式新空对话重启恢复、项目采集去重和数据库完整性。
- 网关 12 项 pytest 测试通过，包括 24 小时租约保持同一 ID、过期不能复活、设备隔离、撤销和敏感字段过滤。
- macOS 隔离 QA 窗口通过真实 Tauri 命令读取本机演示日志并渲染来源与长内容；浏览器检查了 320 像素宽布局和早间关键词查找。
- 24 小时测试为模拟时间验证，不是实际网页账号连续通话 24 小时的承诺。
