# v2.19.2 · 项目驾驶舱与回复修复

## 修复与入口

- 桌宠语音字幕保留完整回复，不再只保留末尾 180 字。回复窗口随内容增高，最高 480 逻辑像素并受屏幕边界限制；长内容可滚动、选择复制，支持收起、重新展开和跳转完整对话。猫咪窗口仍是 200 × 200，回复窗口优先显示在猫咪上方。
- 助理顶部「数据源」显示项目、工作包、Notion、Hermes、语音和本机记忆的实际状态；项目驾驶舱进一步分开 Git、GitHub CI 和本地检查记录。读取失败保留上次快照并明确标记，不能把失败当成空数据。
- 本机项目每 15 秒采集 Git 分支、提交和改动，GitHub 记录最多缓存 60 秒。最近 Release 的文件数量和下载入口独立显示，CI 通过与安装包发布分开判断。需要在每台设备上明确连接项目目录。
- 工作包包含节点、状态、依赖、阻塞、目标日期和下一步；保存追加版本，提供修改时间线。既有对话与记忆不被重置。
- 工作包可关联项目内的 Spec、设计文档、决策和代码行。首次登记保存资料快照及 SHA-256；之后可核对当前文件变化。相对路径、目录授权、文本大小和敏感配置排除均由原生端检查。文件变化提示仅表示需核对，不自动认定计划偏差。
- 设置中可选择「项目关键事件简报」或每日简报时间，默认关闭。应用运行时，提交、检查结果或工作包版本变化会生成文字简报，两分钟内合并事件。通话中播报还需开启「主动汇报」。退出、休眠时不唤醒电脑；定时简报超过半小时不补发。

本地构建与测试结果需通过 `scripts/pm-check.py` 记录，不能推断任意终端中过去的执行结果。详见 [项目驾驶舱](project-cockpit.md)。

## 版本和发布

2026-09-15 核对：`v2.19.0` 和 `v2.19.1` 的 Release 流程均已完成，分别有 17 个下载文件。此前界面中的版本信息不够一致；本地未提交的驾驶舱功能也未包含在这两个安装包里。

本版统一 package.json、Cargo.toml、Cargo.lock 与 tauri.conf.json 为 2.19.2。`scripts/release-version.mjs --release` 验证版本、标签和构建提交一致。Release 在草稿中构建，四个平台的更新包和签名齐全后才公开发布并更新自动更新入口；失败时不会公开一个空版本。

## 验收边界

前端与原生检查覆盖项目状态、未知/过期来源、依赖节点、记录重启恢复、资料路径及快照、简报事件/时间去重和版本冲突。浏览器与独立 macOS 验收应用使用标明演示的长回复检查滚动和跳转，不调用外部语音服务。

本轮没有实现后台唤醒词识别。点麦克风、静音和结束通话是明确的客户端控制；模型理解自然语言不等于本地唤醒词检测。既有跨设备记忆中心的本地工作保留，不包含在本次发布中。
